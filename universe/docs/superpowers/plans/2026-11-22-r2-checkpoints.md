# Universe R2 checkpoints implementation plan

**Goal** — One launcher publishes a recoverable save every 15 minutes when story data changed. **Save now** does the same from any chat while SillyTavern is running.

**Baseline** — Follow the [approved design](../specs/2026-11-22-r2-checkpoints-design.md). Use the existing R2 transport, strong ETags, 60-second lease renewal, Node built-ins, and SillyTavern 1.19.1. Preserve the current graceful-stop handoff. Run one task through the workspace implementer, adversarial review and operator commit cycle before starting the next.

**Review focus** — A group save spans two requests. A manual click can arrive after another capture starts. An upload can outlive local edits. R2 can accept a commit whose acknowledgement never arrives. A stalled or disconnected tab must release the capture barrier.

## Task 1 — Recoverable captures independent of the live data

Files: create `checkpoint-store.mjs` and `checkpoint-store.test.mjs`. Update `local-session.mjs`, `launcher.mjs` and `launcher.test.mjs`. Paths in this plan are relative to `universe/`.

- [ ] Add `captureCheckpoint({ dataRoot, stateRoot, rootId, base, confirmedFiles })` and `publishCheckpoint({ cloud, capture, finish })`. Capture into `<stateRoot>/checkpoints/<operationId>/`. Reuse `snapshot`, `storyPath`, `readRegular`, `atomicFile` and the portable path validator. Return an unchanged result when path and hash inventories agree. Include removals in the manifest. Store the bytes required for retry by hash, and verify each hash against its inventory entry.
- [ ] Record version 2 journal fields for the confirmed base and inventory, active editing state, and optional completed capture. Publish the durable capture marker last. Never reference temporary bytes as a complete capture. Reuse `CloudSave.upload`, `commit(manifest, finish)` and the ancestry check. A live commit uses `finish = false`. Atomically advance the local base only after acknowledgement or ancestry confirmation. Keep edits accepted after capture for the next checkpoint.
- [ ] At restart retry completed captures from staged bytes. Preserve unconfirmed working data on divergence or interrupted multi-file saves. Read existing v1 clean, restoring and publishing journals. Verify v1 publishing bytes against the recorded manifest. Preserve a v1 editing tree for explicit reconciliation. Release only staging data proved obsolete by the durable journal. Adapt the existing final-save path to the same primitives.
- [ ] Verify `node --test checkpoint-store.test.mjs launcher.test.mjs`. Assert unchanged inventory issues zero checkpoint requests, three edits to one file yield one final blob, deleting the last chat yields an empty inventory, and no credentials enter the capture. Interrupt before and after writing the marker, inject a blob failure and a lost commit response, and edit the live transcript before retry. Assert the acknowledged revision restores its original bytes, newer local edits survive and stale writers cannot advance the head.

## Task 2 — A consistent capture boundary in the real chat

Files: create `integration/pinned-hooks.mjs`, `integration/server-bridge.mjs`, `integration/browser-bridge.js` and `integration/barrier.test.mjs`. Update `child.mjs` and `child-preload.mjs`. The installed upstream tree remains an installation input. Keep hook source in Universe so the second PC gets exactly the same behavior.

- [ ] Prepare a version- and source-hash-checked adapter for 1.19.1. Use a child-scoped Node module loader for the pinned server entry and serve the three instrumented browser modules at their original URLs ahead of the static handler. Restrict substitutions to exact known anchors in `src/server-main.js`, `public/script.js`, `public/scripts/group-chats.js` and `public/scripts/world-info.js`. Verify input hashes before launch. Preserve the normal child startup handshake and verify the webpack worker path on a clean install. A hook mismatch must surface as checkpoints unavailable and prevent any live publication.
- [ ] In the server adapter, mount the same-origin Universe plugin router behind `requireLoginMiddleware` and CSRF. Mount the story-write gate **before** `setupPrivateEndpoints(app)`. The stock plugin loader runs later and cannot by itself guard those routes. Track active mutating requests for chats, groups, characters and world info until the handler's writes finish. Include import, rename and delete, and callbacks that continue after a client disconnect. Keep checkpoint control traffic outside the gate.
- [ ] In the browser adapter, register page sessions; track generation start/end and `isGenerating()`, the debounced solo chat save and its completion, `saveGroupChat` through its deferred `editGroup` / `_save`, `saveCharacterDebounced` through `createOrEditCharacter`, and `saveWorldInfo` through its debounced `_save`. A returned promise from the group transcript POST alone leaves the group edit outstanding. Record save failures, including upstream paths that report failure and return normally. Flush only pending local saves; never submit text still in the composer.
- [ ] Implement `withCaptureBarrier(requestId, capture)`. Tell participating tabs to finish turns already started and drain dirty saves, queue newly started mutations, then wait for the acknowledged tab epoch and server writes to drain. Recheck membership after a new page joins. Run Task 1's local capture while writes are held. Always release in `finally` **before** uploading. Keep the UI responsive. Expire a manual wait after 60 seconds; a missing acknowledgement, failed flush or unproven boundary returns pending. Coalesce busy automatic requests and retry at the next completed turn or save.
- [ ] Verify the real hooks in a disposable local profile before enabling live publication. Pause between group transcript and metadata updates, while a card or world edit is debounced, and while a generation starts during a barrier. Test two tabs, then ten; include a tab disappearing, a late join and a client disconnect mid-write. Assert each capture contains all or none of a logical save, later edits proceed, timeout unblocks the UI and release happens even when local capture fails. Run `node --test integration/barrier.test.mjs` and repeat the save operations through the actual pinned UI.

## Task 3 — Schedule, button and end-to-end verification

Files: create `checkpoint-queue.mjs` and `checkpoint-queue.test.mjs`. Update `launcher.mjs`, `server.mjs`, the two integration bridges, `launcher.test.mjs` and `README.md`. Record verification under `docs/verification/`.

- [ ] Replace the 30-second staging loop with one `900000` ms timer started when the writer is ready. Expose `requestCheckpoint(source)` for `timer` and `manual`. Serialize capture and publication. Share results for requests covered by the same capture; a click after capture gets a follow-up covering its newer saved edits. Coalesce missed ticks after sleep. Keep the 60000 ms lease heartbeat independent. During graceful stop, drain any in-flight commit and use its confirmed base for the final save or owner-checked release.
- [ ] Add `POST /api/plugins/universe/checkpoints` and `GET /api/plugins/universe/checkpoints/status` on the same-origin bridge. Return a request ID and state on admission. Rate-limit and coalesce manual requests; allow only fixed, validated IPC commands to the launcher. Expose state, pending work and confirmed timestamp to the active profile. Keep cloud credentials in the parent. Preserve the existing read-only launcher status endpoint.
- [ ] Put **Save now** in `#extensionsMenu`. Provide immediate, keyboard-accessible feedback beside it: **Waiting for current turn**, **Saving…**, **Saved at [time]**, **Already up to date**, **Checkpoint still pending**, or **Save failed — retry**. Show **Cloud save is not configured** in local-only mode. A no-change check retains the last confirmed time. Share result state across tabs.
- [ ] Run `node --test launcher.test.mjs checkpoint-store.test.mjs checkpoint-queue.test.mjs integration/barrier.test.mjs`. With a controllable clock assert one tick at 15 minutes, none at 14:59, ten tabs sharing one timer, zero idle checkpoint requests and an independent renewal every minute. Exercise click-during-capture, click-during-upload, overlapping stop, lease loss and interrupted v1/v2 editing journals.
- [ ] In the real local UI, verify desktop, phone width, keyboard, progress and retry with synthetic chats. Confirm one actual timer revision and one button revision directly in R2 **while the writer is still running**. Restore and compare the exact text from each revision in an isolated profile. Test second-writer exclusion while the lease is held and normal takeover after release or simulated expiry. Record revision IDs, outcomes and any unverified environment; exclude credentials and private story content.
