### Step 1. Save and replay a reversible correction

Files: `scribe/core/ScribeLog.js`, `scribe/core/ScribeReplay.js`, `scribe/page/ScribeKeeper.js`, `scribe/bench/BenchView.js`, `tests/scribe-operator.test.mjs`, `tests/scribe-facts.test.mjs`, `tests/scribe-keeper.test.mjs`, and the shipped userscript.

- Add `ScribeLog.Ruling.EditFact = 'EditFact'` and `Rulers.EditFact(operation, view, outcome)`. Continue through `keeper.rule(operation, resolution = null)`, `ScribeLog.rule`, `ScribeLog.file` and `ScribeKeeper.saveBook`. A request carries `{type, fact, expected, text}`. Capture `expected` on opening the editor with the exact previous text, subject, category, target ID and target text, citation, status, hidden flag and pin state. Validate that snapshot against the current fact on Save. Permit the statuses accepted by `ScribeReplay.live`, including a currently pinned synthetic fact. Trim outer whitespace, retain internal wording and punctuation, and require `ScribeLog.worded(text)`. Reject a mismatched snapshot with the existing stale-state refusal. An unchanged value writes zero log entries.
- Include a deterministic audience snapshot in `expected`. Preserve the three meanings of `widened` (null, Everyone, or a sorted list of distinct subject IDs), and store `told` as a sorted list of distinct subject IDs. Compare those values and `hidden` on submit. Array insertion order alone does not make the dialog stale. A saved Widen, Told or revoke that changes the audience does.
- Before writing, check the proposed effective wording against replay's actual fixed/list deduplication keys, subject and target. If replay would coalesce the corrected row with another row and discard a fact ID, citation or audience, refuse with “This wording would combine two facts. Choose distinct wording.” Preserve both rows and the draft. Identical text on an independent relation target or in a different category remains eligible.
- Build the stored operation from the replayed fact. Record the fact ID, original and corrected wording, subject, category, target identity, and the source message ID and fingerprint when present. Preserve how the fact was created and who knows it. Use the existing book save for the ruling and evidence together. Keep old books readable without a migration. Attach applicable resolution evidence through `ScribeLog.link` only when the identified fact and corrected value settle the point.
- In `ScribeReplay.run`, collect effective corrections in log sequence order, excluding withdrawn entries. Apply effective wording when materializing the targeted fact, including `file`, `succeed` and the pinned winner in `Pinning.Pin`. Use the corrected wording in the normal fixed/list deduplication, conflict derivation, aliases and relationship projections. Preserve the pin's winning fact and audience even when the pin retained the original spelling. Keep the stable fact ID and original source position. A later story replacement remains the current fact and the edited predecessor stays in history. For reallocated IDs, reuse the source and value matching behind `ScribeReplay.supportedFact` only when that match is unique for the original citation, fingerprint, subject, category and target. An uncited edit can follow only its original ID. Reuse original source evidence for consecutive edits even when the second edit started with corrected wording.
- Add `BenchView.Summaries.EditFact(operation)` and use the existing Rulings made list and revoke control. Show fact ID and both wordings. Revoking the newest edit reveals its predecessor. Revoking an earlier edit while a later edit survives preserves the later operator decision. Reuse `ScribeReplay.run` and its existing persisted ruling evidence to recalculate the affected conflicts after revocation.
- Tests use a saved bounty relation toward Mirra and a second relation toward a different target. Assert the actual replayed amount changes from 100,000 to 50,000, the fact ID, target, cite, status and audience survive, the source log operation remains intact, and a JSON round trip reproduces the result. Cover duplicate or stale submissions, two edits with out-of-order revocation, a concurrent Widen, fixed and disputed values, a synthetic pin, a later story replacement, equal value under a different subject/target, ambiguous source matches and an unrelated reread. Inject a failed book write and confirm zero durable edits and a successful single retry.
- Try editing a fixed alternative and a list member into an existing same-slot wording with a different source or audience. Assert the inline refusal, retained draft, zero saved entries and both original IDs/citations. Include a different-target relation control. Change just `told` while editing, then change just the list inside `widened` in a separate run. Both saves must refuse as stale even with unchanged wording and hidden flag. Reverse the order of the same audience IDs as a passing control.
- Run `node --test tests/scribe-operator.test.mjs tests/scribe-facts.test.mjs tests/scribe-keeper.test.mjs tests/scribe-pack.test.mjs`. Mirror shipped sources by visible edit and compare against `ScribePack.build(read)` with CRLF normalized.
