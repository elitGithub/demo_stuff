# Reject automatic reminder refusals

20 November 2026. One implementation task for the [approved design](../specs/2026-11-20-scribe-writer-refusals-design.md). Use the existing JavaScript userscript, room record and Node test harness. The local check adds zero model calls and zero dependencies.

## Task 1. Keep a rejected recap pending through generation, restore and send

- [ ] In `scribe/page/ScribeReminder.js`, add `ScribeReminder.declined(text): boolean` for generated recap text. Use the same heading/label normalization as `told(text)`, retaining enough punctuation and attribution to distinguish dialogue. Recognize clear writer-directed openings such as “I can't write this story”, “I'm sorry, but I cannot continue this roleplay”, and “I can offer a summary instead”. Handle straight and curly apostrophes, case, and a refusal followed by a template or story paragraph. Match the writer's refusal to perform the task. A quotation attributed to a named character, “Mirra can't write the letter”, or narration mentioning a refusal remains eligible. Keep the accepted text and existing size limits intact.
- [ ] In `scribe/page/ScribeLive.js`, check the writer answer in `recount(live, view, now)` before caching or composing. Give a declined response its own stable reason under `Settings.Messages`. Use the existing keyed `record.untold` path for an unavailable recap. Record the original paid request normally. Park the refused input key so polling, redraws, reloads and ordinary sends cannot repeat that paid request. Use the existing eligible generation path for a new story key or an intentional retry. Protect this path with the existing room/epoch checks.
- [ ] In `ScribeLive.load(live, saved)`, validate stored automatic `story.text` and the story portion of `ready` beginning with the existing Scribe marker and recap heading. Handle an orphaned preview with a valid basis but no cached story and an orphaned cache with no preview. Invalidate just the matching automatic offer/cache and its freshness metadata. Associate a parked refusal with the rejected story key when available. An old cache and a different valid offer must be handled independently. A rejected automatic candidate must also stay unavailable in the immediate send path, including after a Worker restore or a failed local write.
- [ ] Preserve operator ownership across `load`, `lines`, and the delivery receipt path. Retain `selection`, valid `edited` text, unsaved drafts and evidence for an already-attempted send. A matching string alone does not establish automatic ownership. The existing captured manual selection or valid edit has send priority. In Findings, the existing **Resend this reminder with my next message** action explicitly selects the displayed outstanding paragraph. Honor that deliberate choice, including for a legacy refusal. Loading that paragraph or receiving an acknowledgement is never a resend request. Keep the room's interval due after a bare player send. Confirming a later valid reminder resets it once. Preserve separately selected developments under their existing delivery rules.
- [ ] In `scribe/page/PanelView.js` and the existing Live view, map the reason to “The writer declined to produce a recap. Your reminder is still due.” Use the existing grouped warning outlet. Avoid a second generic recap warning for the same event on the same screen. Keep progress counts visible and genuine key, transport and budget failures distinct. Clear the warning when a valid replacement for that pending recap is ready.
- [ ] Add regression cases to `tests/scribe-reminder.test.mjs`, `tests/scribe-live.test.mjs`, and `tests/scribe-panel.test.mjs`. Exercise the refusals and dialogue controls above, refused text plus template, empty answer, valid recap, cache-only, preview-only, valid manual selection identical to rejected text, and outstanding confirmation after reload. Assert exact outgoing text, stored due state, warning count, and provider call counts.
- [ ] Seed `selection: null`, a valid `editedFor`, and a saved edit byte-identical to the rejected automatic preview. Reload, send and confirm the edit once, then verify the automatic copy cannot follow it. In separate restored rooms, leave an outstanding attempt alone and deliver a late receipt, or explicitly click Resend on its visible paragraph. The first room never queues another copy. The second uses the exact selected text and preserves receipt identity so a delayed acknowledgement cannot reset the interval twice.
- [ ] In `tests/scribe-whole.test.mjs`, run the installed script in both composer layouts. Make the writer return the known refusal, send the player's message, and inspect the simulated Zeta request. Expect the original player text, no automatic attachment, one visible warning and a still-due reminder. Repeat after hydrating a pre-fix automatic record. Advance the clock and redraw on the same input with zero additional writer calls. On a new eligible input, return a valid recap containing a character's quoted refusal, deliver it once, and confirm the following send is bare. Exercise a manually queued override byte for byte, including after refresh.
