# Implement the local Universe build layout

Follow the [approved design](../specs/2026-11-22-local-build-layout-design.md). Make one scaffold change before handoff. Run commands through npm in `universe/`.

## Files and entry points

1. Move `server.mjs`, `launcher.mjs`, `child.mjs`, `child-preload.mjs`, `local-session.mjs`, `checkpoint-store.mjs`, `story-files.mjs` and `r2.mjs` to `src/`. Move `cloud-save.mjs` to `src/classes/cloud-save.mjs`. Extract the existing `CaptureGate` class to `src/classes/capture-gate.mjs`. Move `server-bridge.mjs`, `browser-bridge.js` and `pinned-hooks.mjs` to `src/integration/`. Update imports and the loader URLs used by the child. Preserve the existing exports used by the application and their behavior.
2. Move `launcher.test.mjs`, `checkpoint-store.test.mjs` and `integration/barrier.test.mjs` into `tests/`. Move the sample card to `tests/fixtures/story-tests/mara-vale.json`. Update test imports and fixture paths. The original checkpoint scenarios must still run through `npm test`.
3. Keep one root npm manifest. Set `build` to `node scripts/build.mjs`, `start` to `node scripts/build.mjs --if-missing && node dist/server.mjs`, and `test` to `node --test tests/*.test.mjs` or the explicit equivalent listing those suites. The existing `.npmrc` disables implicit lifecycle scripts, so the explicit start command prepares the build. Keep all dependency versions and overrides.
4. Implement `scripts/build.mjs`. Assemble the contents of `src/` at `dist/`, including `dist/server.mjs`, `dist/classes/` and `dist/integration/`. Include the pinned dependency tree at `dist/node_modules/sillytavern` using the root manifest and lockfile, npm's shallow install strategy, `--ignore-scripts`, and the existing project npm cache. Use locked package inputs for the dependency bundle. Build source and package inputs exclude `.env`, `local/` story/configuration files and test fixtures. Keep generated output out of Git with `/dist/` in the project `.gitignore`.
5. Use a completion marker in generated output. Prepare the build away from the published entry point and expose it only on success. A repeated `npm run build` must be safe, and `--if-missing` may reuse a completed build with its required entry points present. Preserve an existing completed build on failure. Limit replacement or cleanup to generated `dist/` output owned by the build and temporary directories created by this build. A pre-existing unrecognized output directory must survive. The operator's installed source runtime and active profile are outside the build write set.
6. Resolve the project root relative to the module's parent directory, whether running under `src/` or `dist/`. The launcher reads the root `.env` and uses the current `local/config.yaml`, `local/data/`, `local/data.universe/` and legacy-path checks. Built code resolves SillyTavern from `dist/node_modules`, including when root `node_modules` also exists. Preserve the source-mode and synthetic-root overrides used by the tests. Update the README's layout, npm commands and paths.
