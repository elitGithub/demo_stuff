# Implementation plan — Zeta Memory's three session helpers

The operator approved the [three-helper design](../specs/2026-11-19-session-helpers-design.md) on 19 November 2026 and added a delivery requirement. A sent reminder clears automatically. The operator chooses the number of user messages between reminders, as in DM Memory.

**First task for approval: Task 1 only.** The numbered tasks are in execution order. Within each task, an implementer builds the change, then adds the listed regression tests. A fresh adversarial reviewer must give a reproducing input for each finding. The orchestrator checks each claim, brings fix rounds to the operator, and obtains a scoped re-review. Hand off one task and wait for the operator's commit before proposing the next. This document authorizes no implementation.

Paths below are relative to the demo. Use the existing Node test runner, fake clocks, storage, locks, frame and model. Run each named suite individually with `node --test tests/<suite>.test.mjs`. For each task changing shipped JavaScript, rebuild `scribe/scribe.user.js` with `node scribe/pack.mjs` and run `tests/scribe-pack.test.mjs` before handoff. Preserve in-progress source changes. Keep room exports under the ignored `scribe/private/` directory.

## Task 1 — Clear a delivered reminder and count the next interval

**Files.** `scribe/page/ScribeLive.js`, `ScribeSender.js`, `ScribeFrame.js`, `ScribeBoot.js`, `ScribeKeeper.js`, `ScribePanel.js` in the same directory. Tests: `scribe-live`, `scribe-sender`, `scribe-frame`, `scribe-boot`, `scribe-panel`, `scribe-whole`. Reference only: `zeta-dm-memory.user.js`, its `turnCount + 1 >= interval` preview and room interval.

1. Trace the existing panel Force → prepared text → composer → actual user message → `sent`/`went` → panel redraw in both top-page and chat-frame paths. Capture which step leaves the operator's reminder visible. The existing `skip(record)` resets several fields already. Check stale drafts, frame acknowledgements, async preparation finishing after delivery, and rearming after reload before attributing a cause.
2. Keep the single per-room setting `refresh`, labelled **User messages between reminders**, positive integer, default **6**. Honor existing saved values, including 8 and 10. One chosen interval per room. With interval 8 and seven confirmed user sends since the last delivery, prepare for send **8**. Each accepted user message counts once. Storyteller replies, regenerations, echoes, cancelled entries, rerendering, and clicking Force do not increment it. Changing the interval retains the count; lowering it below the current count makes the next send eligible. A manual send starts a new interval on delivery.
3. Extend the existing `lines(live)`, `outgoing(live, text)`, `sent(live)`, `went(live, lines)` and frame offer/report with a room-scoped reminder ID and a send-attempt ID independent of paragraph text and frame arm sequence. Keep the identity through retries; a new manual request after delivery gets a new ID. Persist the pending delivery and counted user-message identity in the room's existing Live record. Use the sender confirmation to clear the matching queued preview, forced flag, matching edit/draft and composer attachment immediately; disarm all frames, reset the count to zero and invalidate late preparation for that ID. Preserve an independently edited newer draft.
4. Reconcile an interrupted acknowledgement with the room's outgoing player messages after reload. Match an attached block on a **new** player message after the recorded send boundary, with room, player message ID/fingerprint and the offered content. A typed but unsent draft or an echoed storyteller block cannot settle delivery. If outcome is unknown, show it as awaiting confirmation and reconcile before re-offering. An actual send without room for the paragraph counts once and leaves the reminder due. Never send an extra chat message automatically.

For a pre-upgrade Live record with a stuck preview and no delivery ID, compare the saved offer with the owned reminder block on the player message immediately following its recorded target. The Unchained Princess export gives a concrete example: the saved #896 offer matches the block on #897. Consume that offer once, seed the counter from later distinct player messages, and show no preview for it on reload. An uncertain match stays visible for reconciliation. Normalize absent new fields when loading existing room settings and Live records.

**Break it.** Force → send once → pending text, badge and composer attachment clear without Clear; immediately send again → zero attachments. Repeat with an edited reminder, identical text on two different offers, Enter and click firing together, duplicate frame report, report from a previous room, two tabs, reload between send and acknowledgement, and an earlier writer response arriving after send. A cancelled or failed send stays pending and does not reset the count. For 6, 8 and 10, verify attachment on exactly N and 2N under normal ready conditions, including after reload. Manual delivery on turn 3 with interval 8 makes turn 11 the next regular target. Test both actual browser-entry harnesses, not only direct calls to `went`.
