## Global constraints

- Only notes synchronize; interval, counter, inject-next, and collapsed state stay local.
- Existing bindings are `DB` and `DM_API_KEY`; no additional cloud resource or paid feature.
- Key: 60-254 visible ASCII characters inclusive (U+0021 through U+007E), including punctuation; no whitespace or control characters. Sent as an HTTPS bearer token. This correction was explicitly approved on 2026-11-10.
- Room: exact pathname, 1-512 UTF-8 bytes, leading slash, valid Unicode, no whitespace, control character, backslash, question mark, or fragment marker.
- Notes: valid Unicode, at most 65,536 UTF-8 bytes, preserve whitespace; empty string is valid.
- PUT JSON body: at most 524,288 streamed bytes; exactly `notes` and `expectedRevision`.
- Revision: nonnegative safe integer on input; stored positive integer; no historical copies.
- Index: default 25, maximum 50, binary room-ID order, last-ID cursor, no notes or totals.
- Rate limit: 180 authenticated valid requests per UTC minute across all browsers.
- No website, PATCH, DELETE, cookie authentication, permissive CORS, credential logging, or automatic upgrade.
- All application responses set JSON content type, `Cache-Control: no-store`, and `X-Content-Type-Options: nosniff`; normal HEAD response-body rules still apply.
- Only the operator executes application SQL and deploys. No dependency installation, application-DB access, environment-file reads, file deletion, Git writes, or worktree creation.
- Work in this checkout. The orchestrator writes documentation and verifies claims; an implementer subagent writes all product/test code.
- Code first, then adversarial tests. No tests are run against the application database.
- General AGENTS.md rules remain in force; Laravel/PHP tooling is not applicable to this approved JavaScript project.

## Review focus

1. A literal percent-encoded path segment must not be decoded twice or merge two rooms; pin this in HTTP validation tests.
2. Streamed bodies can exceed their declared length or contain invalid UTF-8; bound bytes before JSON parsing and pin both cases in HTTP tests.
3. Competing saves and a lost response must not create false success or silent replacement; pin statement-level acceptance in SQLite tests.
4. A delayed rate-limit request from the previous minute must not reset a newer counter; pin reverse arrival order in SQLite tests.
5. Wrong credentials must never reach D1, including during a database failure; pin error precedence, headers, and redacted diagnostics in HTTP tests.

#### Step 2: Implement authentication and request validation

- [ ] Implement these methods on the Worker object. Names and return shapes are fixed; internal local-variable choices are left to the implementer.

| Signature | Contract |
|---|---|
| `fetch(request, env): Promise<Response>` | Entry point, controlled errors, safe diagnostics and response headers |
| `authenticate(request, secret): Promise<void>` | Validate configured key; check bearer token using SHA-256 digests and `crypto.subtle.timingSafeEqual` |
| `parseCommand(request): Promise<Readonly<Command>>` | Validate HTTPS, route, method, query, and applicable body before D1 access |
| `validateRoomId(value): string` | Validate and return an unchanged room ID; reused for cursor validation |
| `readSaveBody(request): Promise<Readonly<SaveInput>>` | Stream cap, fatal UTF-8 decoding, JSON parse, exact keys, Unicode and revision validation |
| `failure(code, headers): Error` | Attach a named controlled error code and optional Allow/Retry-After headers; no sensitive values |
| `respond(payload, status, headers): Response` | Serialize JSON and apply the mandatory privacy headers |

`SaveInput` is a frozen `{ notes, expectedRevision }`. Commands are frozen discriminated records: Read `{ kind, roomId }`, Save `{ kind, roomId, notes, expectedRevision }`, or List `{ kind, limit, after }`, where `after` is null or a roomId. These are runtime-validated readonly records; no unchecked request object crosses into storage methods.

- [ ] Enforce the order: validate server secret and authenticate; validate request; validate DB binding; claim rate slot; execute room operation. A valid-looking wrong token and a missing token return 401 even if DB is absent. Missing/malformed server secret returns 503. Reject non-HTTPS with 400, without redirecting credentials.
- [ ] Accept the case-insensitive Bearer scheme followed by one space and 60-254 visible ASCII token characters, including punctuation. Validate configured and supplied keys identically, without trimming, normalization, or decoding. Reject duplicate/combined authorization values and URL-supplied credentials. Compare digests of equal 32-byte length; never replace the production comparison with JavaScript string equality.
- [ ] Routes: `/v1/memory` supports GET and PUT, requires exactly one `roomId`; `/v1/memories` supports GET, allows at most one `limit` and `after`. A supplied limit is decimal digits denoting 1-50; blank or malformed is 400. An absent limit becomes 25; an absent after becomes null; an explicitly empty cursor is 400. Unknown route 404; wrong method 405, with `Allow: GET, PUT` or `Allow: GET`.
- [ ] Reject bad percent escapes and invalid UTF-8 in raw query components before accepting their parsed value. Preserve a literal percent sequence in the resulting identifier: `%252F` becomes `%2F`, not `/`. Treat plus according to normal query-string rules; resulting whitespace fails room validation. Reject duplicate parameters even when their names use different percent spellings. Never normalize the parsed room identifier further.
- [ ] Accept PUT media type `application/json`, case-insensitive, with no charset or charset=utf-8; reject other media types/charsets with 415. Content-Length cannot bypass streamed counting. Cancel/release the reader when exceeding 524,288 bytes. Invalid encoding/JSON, null/array payloads, unknown/missing fields, non-string notes, unpaired surrogates, booleans/fractions/negative/unsafe revisions return 400. Oversized notes return 413. Preserve empty notes and all valid whitespace. GET with a body is 400.

#### Step 3: Implement conditional SQL operations and the request limit

- [ ] Define these interfaces and static statement names on `worker.mjs`:

| Signature | Result |
|---|---|
| `execute(db, statementName, values): Promise<ReadonlyArray<Row>>` | Run one named bound statement; map thrown errors or unsuccessful D1 results to 503 |
| `claimRateSlot(db, nowMs): Promise<void>` | Use UTC-minute start; throw controlled 429 with Retry-After when full |
| `loadMemory(db, roomId): Promise<Readonly<Memory>>` | Return record or 404 memory_not_found |
| `saveMemory(db, roomId, input, updatedAt): Promise<Readonly<SaveResult>>` | Atomically return `{ status, memory }`, or 409 |
| `listMemories(db, limit, after): Promise<Readonly<Page>>` | Return frozen metadata items and nullable cursor |

Memory fields are exactly `{ roomId, notes, revision, updatedAt }`; Page fields are `{ items, nextCursor }`. Row is the typed driver boundary only. Freeze returned records and page items; no loose driver rows are passed onward as undocumented layer contracts.

- [ ] `ReadMemory`: select the four explicit columns for `room_id = ?1`, aliasing snake_case columns to the HTTP field names. Return 404 for no row.
- [ ] `CreateMemory`: insert `(roomId, notes, 1, updatedAt)`, use `ON CONFLICT(room_id) DO NOTHING`, and RETURNING the four aliased columns. Select this statement only when expectedRevision=0. One returned row means 201; none means 409. Do not use REPLACE or a preliminary existence check.
- [ ] `UpdateMemory`: one UPDATE with `WHERE room_id = ?1 AND revision = ?2`, notes parameter ?3 and timestamp ?4. Compute revision and updated_at with CASE expressions comparing the old notes against ?3: unchanged text keeps both old values; changed text increments revision and uses ?4. RETURNING the four aliased columns gives the accepted snapshot even if another request writes later. One row means 200; none means 409. The schema's safe-integer ceiling must prevent overflow; a constraint failure returns 503 without a partial change.
- [ ] `ListFirst` and `ListAfter`: select only roomId/revision/updatedAt, ORDER BY room_id COLLATE BINARY ASC, LIMIT limit+1. ListAfter adds the indexed predicate `room_id > ?1 COLLATE BINARY`; avoid an optional-cursor OR that could cause a full scan. Trim the lookahead item; nextCursor is the last emitted roomId only if that extra row exists. Do not sort in JavaScript.
- [ ] `ClaimRateSlot`: one INSERT/ON CONFLICT conditional UPDATE/RETURNING for id=1, incoming `window_start = floor(nowMs/60000)*60`, initial count 1. Reset to count 1 only when the incoming bucket is strictly newer; otherwise increment the current count only below 180. An older incoming bucket must never lower window_start. At capacity, return no row and leave both columns unchanged.
- [ ] `ReadRateWindow`: on a rejected claim, read the existing bucket and set integer seconds `Retry-After = max(1, ceil(((window_start+60)*1000-nowMs)/1000))`. A missing counter at this point is 503, not unlimited access. A claimed slot remains spent when the room operation fails. Rate and room statements need not share a transaction.
- [ ] Use positional placeholders only; no interpolation of room IDs, notes, cursors, timestamps, limits, or counters into SQL. Do not enable D1 read replication or introduce a cache. SELECT and RETURNING use the same explicit field aliases.
