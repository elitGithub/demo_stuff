# Scribe reminders, reading progress, and ruled issues implementation plan

**Ready for plan approval · 19 November 2026**

**Goal.** Send the paragraph the operator selected, clear it on confirmed delivery, finish reading every available message, honor the room’s reminder interval, and close issues when a ruling settles them. [Approved design](../specs/2026-11-19-scribe-visible-reminder-and-read-progress-design.md)

**Architecture.** Findings owns the text visible at click time. Live owns the room’s selection, send attempts, and counter. Keeper owns saved reading coverage and durable book decisions. The top page and frame use the same offer and receipt protocol. All paths below are relative to `zeta-dm-memory/`. Use the existing plain JavaScript modules, Tampermonkey bundle, and Node test harness.

## Execution and verification

Use the repository’s subagent-driven execution loop, one approved task at a time. For each task, a native OpenAI implementer changes the source first and adds the listed regression tests. A separate adversarial reviewer must provide a reproducing input for each finding. The orchestrator verifies each claim. The operator rules on fix rounds and approves the next task after committing. Use synthetic rooms, fake receipts, clocks, stores, and model responses.

For each task that changes shipped code, mirror its source changes into `scribe/scribe.user.js` through a visible edit. Compare the checked-in script to `ScribePack.build(read)` from `scribe/pack.mjs` with CRLF normalized, run `node --test tests/scribe-pack.test.mjs`, and run the task’s command from the demo directory. A pass requires bundle equality, zero test failures, and the observable outcomes below. Update older assertions that deliberately expected the newest message to remain unread or an explicitly selected draft to need resaving. Keep tests for automatic freshness and delivery uncertainty.

**Review focus.** Try a redraw between click and send (Task 1), a late receipt after a new edit with identical text (Task 2), a failed save on the last message (Task 3), duplicate acknowledgements from two tabs (Task 4), and a durable ruling followed by a failed Live save (Task 5).

## Task 5. Close only issues resolved by a saved ruling

**Files.** `scribe/core/ScribeLog.js`, `scribe/core/ScribeReplay.js`, `scribe/page/ScribeKeeper.js`, `scribe/page/ScribePedant.js`, `scribe/page/ScribeLive.js`, `scribe/page/PanelView.js`, and `scribe/page/ScribePanel.js`. Tests in `tests/scribe-operator.test.mjs`, `tests/scribe-facts.test.mjs`, `tests/scribe-pedant.test.mjs`, `tests/scribe-live.test.mjs`, `tests/scribe-panel.test.mjs`, and `tests/scribe-whole.test.mjs`.

- [ ] Extend the keeper handles `rule(operation, resolution = null)` and `file(operations, anchor, resolution = null)`. Carry optional resolution evidence on the accepted log entry in the same book save. Identify the disputed point by its stable fact/question/conflict IDs and the applicable supporting passage IDs, fingerprints and fact values. For multiple filed operations, link only the accepted operation(s) that settle that point. Validate links against the replayed room state. An unrelated decision about the same subject cannot settle it.
- [ ] In Findings, “Rule it...” currently prefills the Rulings editor. Retain the originating finding through preview and confirmation. Prefill, preview, an edited-away proposal, a refused operation, Cancel, Leave open, and a failed book save leave it actionable. Cover the direct Findings ruling via `ScribeLive.told(live, key)` and the Rulings form via `ScribePanel.rule(panel, outlet, operation, question)`. Resolve direct form choices against the same evidence even without a Findings origin.
- [ ] Derive settled issues from valid, unrevoked book decisions during replay. Use the same result for active Findings, pending Rulings, Summary and counts. Preserve history and the decision’s provenance. Show an answered item awaiting processing outside the actionable queue and preserve recovery when an answer cannot be read. Match older entries only when IDs and evidence establish a unique resolution. On partial failure, use the saved book decision for the immediate redraw and reload, then repair Live when writable. Rechecking the same evidence cannot recreate the active item. A material supporting change or revocation permits the affected issue to reopen if no other valid decision covers it.
- [ ] Create two disputes about the same character. Rule on one from each normal entry point in separate runs. Assert the actionable count goes from two to one, the other dispute remains, and history retains the evidence and ruling. Repeat after reload, same-evidence recheck, unrelated book revision, material edit and revocation. Interrupt between the book and Live writes and reopen. Assert one durable ruling, correct counts before repair, and no duplicate after repair. Include ambiguous legacy entries and a failed book save. Run `node --test tests/scribe-operator.test.mjs tests/scribe-facts.test.mjs tests/scribe-pedant.test.mjs tests/scribe-live.test.mjs tests/scribe-panel.test.mjs tests/scribe-whole.test.mjs`.
